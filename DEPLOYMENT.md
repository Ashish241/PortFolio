## Architecture and repository

Vercel serves the Vite/React/TypeScript frontend. React Three Fiber renders a
procedural Spider-Man scene; there is no external GLB to host. The frontend
calls a separate FastAPI service using its public `VITE_API_BASE_URL` origin.
Render Free hosts the Dockerized API with HTTP readiness checks and outbound
HTTPS requests to Groq and Resend. Neon Free provides managed PostgreSQL. The API
uses Alembic and an idempotent resume-based seed on startup. Render and Neon
are recommendations, **not provisioned services** until configured in their
dashboards. Vercel's Python Functions are less suitable for this stateful API's
migration and in-memory conversation workflow. Render Free spins down after
inactivity; the first visitor after an idle period can wait about a minute
for the API to wake. Frontend API requests allow up to 90 seconds for this
cold start. Its ephemeral filesystem is not used for the database.

`frontend/` has Vite source, public assets and tests. `backend/` has FastAPI,
SQLAlchemy models, Alembic migrations and tests. `content/portfolio.json` is
the verified resume snapshot and database seed. The API stores contact
messages and delivery status in PostgreSQL. Its `/api/health` checks process
liveness; `/api/ready` checks database access and the seeded profile.

## Local verification

From the repository root, use Node 22 and Python 3.12. Install frontend and
backend dependencies:

```powershell
cd frontend
npm ci
npm test
$env:SITE_URL='https://port-folio-delta-wine.vercel.app'
npm run build
cd ..\backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements-dev.txt
python -m pytest tests -q
```

Copy `backend/.env.example` to `backend/.env` for local development. Set a
working `DATABASE_URL`; SQLite can be used locally with
`sqlite:///./preview.db`. Then run `python -m alembic upgrade head`,
`python -m app.seed` and `python -m uvicorn app.main:app --host 127.0.0.1
--port 8000`. In another terminal run `npm run dev` from `frontend/`. Vite
proxies `/api` to local port 8000. If that port is occupied, stop the previous
backend before starting another copy.

## 2. Configure Neon PostgreSQL

Create a production Neon project and database in a region close to Render.
Save the connection string in Render's `DATABASE_URL` secret; include
`sslmode=require`. The backend normalizes standard `postgres://` and
`postgresql://` URLs to its installed `psycopg` driver. Use a dedicated
application database role with only the permissions required for migrations,
seeding, reads and contact inserts/updates. Review Neon backup/restore and
point-in-time recovery settings before launch. Do not expose this URL to Vite
or GitHub Actions. The local SQLite preview database is not production data.

## 3. Deploy FastAPI to Render

In Render, create a Blueprint from **this existing GitHub repository** and
`render.yaml`, on `new-spiderman-portfolio`. This builds `backend/Dockerfile`
using the repository root as context so the verified `content/` seed is
included. Auto-deploy is initially disabled. The Blueprint explicitly sets
`plan: free`; confirm the Render review screen still shows **Free** before
deploying. Set the `sync: false` fields in Render's secure environment UI:
`DATABASE_URL`, `AI_API_KEY`, `CONTACT_RECEIVER_EMAIL`, `EMAIL_FROM_ADDRESS`
and `EMAIL_API_KEY` (the Resend API key). `IP_HASH_SECRET` is generated by
Render. Use the Groq key
only in Render, never in Vercel. The Blueprint already lists the production
origin and the exact known Vercel branch-preview origin in `CORS_ORIGINS`.
Add any different preview URL explicitly and remove obsolete origins later;
wildcards are rejected. If proxy IP handling needs adjustment, set `TRUSTED_PROXY_IPS` to
the trusted proxy addresses specified by the host; do not trust arbitrary
forwarded headers.

The container runs migrations and the idempotent seed before Uvicorn. Render
checks `/api/ready`; deployment should not be marked healthy if PostgreSQL or
the verified profile is missing. Record the resulting `https://...onrender.com`
origin as `BACKEND_ORIGIN`. Check `/api/health`, `/api/ready` and `/api/profile`
over HTTPS. Do not send live contact test messages to real third parties.

For Resend, configure its free HTTPS Email API and verify a sending domain for
general delivery. Resend's free tier is subject to monthly and daily limits.
The contact route commits the message before attempting
email. Delivery is recorded as `SENT`, `FAILED` or `DISABLED`; a successful
contact response means **stored**, not necessarily emailed. Inspect failed
delivery records privately in Neon. Render Free does not provide shell access;
the private `python -m app.retry_email MESSAGE_ID` command can be run locally
with trusted backend environment variables after checking whether Resend
accepted the original email. Its HTTPS request uses a per-message idempotency
key. Do not expose a public message-list or retry endpoint.

## Troubleshooting

`/api/ready` failure means the database or seed is unavailable; check the
Render migration logs and managed database connection/SSL settings. Browser
requests to `localhost` mean `VITE_API_BASE_URL` was missing at build time.
CORS errors mean the **exact** preview or production origin is absent from
`CORS_ORIGINS`. A chat 502 means the Groq request or response failed; 503 can
mean service configuration or database failure. A contact 201 confirms storage
only; inspect private delivery status for email. A Vercel 404 on an asset
means check Root Directory, build output and case-sensitive asset names.
